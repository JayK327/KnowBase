# Data Catalog — Core Tables

## Overview

This document describes the authoritative schemas for all core production tables
in the analytics warehouse. All tables reside in the `prod` catalog under the
`core` schema unless otherwise noted. Schema changes must go through the data
governance review process before deployment to production.

---

## Table: users

**Purpose:** Central identity table for all registered users across web and mobile
platforms. Every other table in the warehouse joins back to this table via `user_id`.

**Owner:** Platform Data Engineering
**Updated by:** user_registration_consumer (Kafka topic)
**Update frequency:** Near real-time, ~30 second lag
**Retention policy:** 7 years (GDPR compliance requirement)
**Row count:** ~48 million as of Q2 2024
**Partitioned by:** created_at (monthly)

### Columns

| Column | Type | Nullable | Description |
|---|---|---|---|
| user_id | UUID | No | Primary key. Generated at registration. Immutable. |
| email | VARCHAR(255) | No | Unique. Lowercased on ingestion. Indexed. |
| username | VARCHAR(64) | Yes | Optional display name. Not unique. |
| created_at | TIMESTAMP | No | UTC registration timestamp. Partition key. |
| updated_at | TIMESTAMP | No | UTC timestamp of last profile update. |
| is_active | BOOLEAN | No | False for soft-deleted or suspended accounts. |
| country_code | CHAR(2) | Yes | ISO 3166-1 alpha-2. Null for pre-2021 registrations. |
| acquisition_channel | VARCHAR(32) | Yes | organic, paid_search, referral, social, direct |
| plan_type | VARCHAR(16) | No | free, pro, enterprise. Default: free. |
| plan_started_at | TIMESTAMP | Yes | Null for free-tier users. |

### Indexes
- `email_idx` on `email` — used by authentication service lookups
- `created_at_idx` on `created_at` — supports time-range queries

### Foreign Keys
- `user_id` is referenced by `orders.user_id`, `sessions.user_id`,
  `user_events.user_id`, `subscriptions.user_id`

### Known Data Quality Issues
- 3.2% of rows have null `country_code` due to migration from legacy system (pre-2021)
- `acquisition_channel` is null for ~8% of users imported from the 2022 acquisition

## Table: orders

**Purpose:** All purchase transactions including one-time purchases and subscription
renewals. Source of truth for revenue reporting.

**Owner:** Commerce Data Engineering
**Updated by:** order_processor_service (writes directly via JDBC)
**Update frequency:** Continuous writes, ~5 second lag
**Retention policy:** 10 years (financial compliance)
**Row count:** ~210 million as of Q2 2024
**Partitioned by:** created_at (daily)

### Columns

| Column | Type | Nullable | Description |
|---|---|---|---|
| order_id | UUID | No | Primary key. |
| user_id | UUID | No | Foreign key → users.user_id |
| product_id | VARCHAR(64) | No | Foreign key → products.product_id |
| status | VARCHAR(16) | No | pending, confirmed, shipped, delivered, cancelled, refunded |
| amount_usd | DECIMAL(10,2) | No | Order total in USD. Always positive including for refunds. |
| currency | CHAR(3) | No | ISO 4217. Stored for international orders. |
| amount_local | DECIMAL(10,2) | Yes | Amount in local currency at time of order. |
| exchange_rate | DECIMAL(10,6) | Yes | USD/local rate at order time. |
| created_at | TIMESTAMP | No | Order creation time. Partition key. |
| updated_at | TIMESTAMP | No | Last status change time. |
| payment_method | VARCHAR(32) | Yes | card, paypal, apple_pay, bank_transfer |
| refunded_at | TIMESTAMP | Yes | Non-null only for refunded orders. |
| metadata | JSON | Yes | Flexible bag for promotion codes, A/B test flags. |

### Notes
- `amount_usd` is always the total regardless of currency. Use `amount_local`
  and `exchange_rate` for local-currency reporting.
- Refund rows reuse the original `order_id`. Do NOT sum `amount_usd` without
  filtering `status != 'refunded'`.

## Table: sessions

**Purpose:** Web and mobile user sessions. Each row represents one continuous
session defined as activity with no gap exceeding 30 minutes.

**Owner:** Product Analytics Engineering
**Updated by:** event_sessioniser (Spark Streaming job)
**Update frequency:** Micro-batch, 5-minute lag
**Retention policy:** 2 years
**Row count:** ~1.4 billion as of Q2 2024
**Partitioned by:** session_start (daily)

### Columns

| Column | Type | Nullable | Description |
|---|---|---|---|
| session_id | UUID | No | Primary key. Generated by sessioniser. |
| user_id | UUID | Yes | Null for anonymous sessions. |
| anonymous_id | VARCHAR(64) | No | Persistent cookie-based ID. Always present. |
| platform | VARCHAR(8) | No | web, ios, android |
| session_start | TIMESTAMP | No | First event in session. Partition key. |
| session_end | TIMESTAMP | Yes | Last event. Null if session still active. |
| duration_seconds | INTEGER | Yes | Null if still active. |
| page_views | INTEGER | No | Count of page_view events in session. |
| events_count | INTEGER | No | Total event count. |
| utm_source | VARCHAR(64) | Yes | Marketing attribution. |
| utm_medium | VARCHAR(64) | Yes | Marketing attribution. |
| utm_campaign | VARCHAR(128) | Yes | Marketing attribution. |
| country_code | CHAR(2) | Yes | Derived from IP geolocation. |
| device_type | VARCHAR(16) | Yes | desktop, mobile, tablet |

## Table: user_events

**Purpose:** Raw event stream table. Every user interaction — clicks, page views,
feature usage, errors — lands here first. This is the source table for all
downstream behavioral analytics.

**Owner:** Data Platform Engineering
**Updated by:** event_ingestor (Kafka → Delta Live Tables pipeline)
**Update frequency:** Near real-time, <1 minute lag
**Retention policy:** 90 days in hot storage, 3 years in cold (S3 Glacier)
**Row count:** ~18 billion events as of Q2 2024
**Partitioned by:** event_date (daily), event_type (for partition pruning)

### Columns

| Column | Type | Nullable | Description |
|---|---|---|---|
| event_id | UUID | No | Primary key. Client-generated. |
| user_id | UUID | Yes | Null for pre-login events. |
| anonymous_id | VARCHAR(64) | No | Always present. |
| session_id | UUID | Yes | Null until session attribution completes (~5 min lag). |
| event_type | VARCHAR(64) | No | Dot-notation namespace: page.view, button.click, purchase.complete |
| event_date | DATE | No | Partition key. Derived from event_timestamp. |
| event_timestamp | TIMESTAMP | No | UTC client-side timestamp. |
| server_timestamp | TIMESTAMP | No | UTC server ingestion time. |
| properties | JSON | Yes | Event-specific payload. Schema varies by event_type. |
| platform | VARCHAR(8) | No | web, ios, android |
| app_version | VARCHAR(16) | Yes | Semver string. Null for web. |
| library_version | VARCHAR(16) | Yes | Analytics SDK version. |

### Important Notes
- Use `server_timestamp` for deduplication and ordering. `event_timestamp` is
  client-reported and can be skewed by device clock drift.
- The `properties` JSON schema is documented per event_type in the Event Registry
  (separate document: event_registry.md).
- Duplicate events (same `event_id`) occur at ~0.3% rate due to SDK retry logic.
  Always deduplicate on `event_id` before aggregating.

## Table: products

**Purpose:** Product catalog. Dimension table for joining with orders.

**Owner:** Commerce Engineering
**Update frequency:** Manual updates via admin dashboard, ~20 changes/day
**Row count:** ~14,000 active products

### Columns

| Column | Type | Nullable | Description |
|---|---|---|---|
| product_id | VARCHAR(64) | No | Primary key. Human-readable slug (e.g. pro-monthly-usd). |
| name | VARCHAR(256) | No | Display name. |
| category | VARCHAR(64) | No | subscription, one_time, add_on |
| price_usd | DECIMAL(10,2) | No | List price in USD. |
| billing_period | VARCHAR(16) | Yes | monthly, annual, lifetime. Null for one_time. |
| is_active | BOOLEAN | No | False means retired/deprecated. |
| created_at | TIMESTAMP | No | |
| deprecated_at | TIMESTAMP | Yes | When the product was retired. |

## Table: subscriptions

**Purpose:** Current and historical subscription states per user.
One row per subscription lifecycle event (activation, renewal, cancellation).

**Owner:** Commerce Data Engineering
**Row count:** ~22 million rows

### Columns

| Column | Type | Nullable | Description |
|---|---|---|---|
| subscription_id | UUID | No | Primary key. |
| user_id | UUID | No | Foreign key → users.user_id |
| product_id | VARCHAR(64) | No | Foreign key → products.product_id |
| status | VARCHAR(16) | No | active, cancelled, expired, paused |
| started_at | TIMESTAMP | No | Subscription start. |
| current_period_start | TIMESTAMP | No | Current billing period start. |
| current_period_end | TIMESTAMP | No | Current billing period end. |
| cancelled_at | TIMESTAMP | Yes | Non-null if cancelled. |
| cancel_reason | VARCHAR(64) | Yes | too_expensive, missing_feature, competitor, other |
| trial_started_at | TIMESTAMP | Yes | Non-null if started with trial. |
| trial_ended_at | TIMESTAMP | Yes | Non-null if trial ended. |

## Cross-Table Join Patterns

### Revenue by acquisition channel
```
SELECT u.acquisition_channel, SUM(o.amount_usd) AS revenue
FROM orders o
JOIN users u ON o.user_id = u.user_id
WHERE o.status NOT IN ('cancelled','refunded')
  AND o.created_at >= '2024-01-01'
GROUP BY 1
```

### Active subscriber count
```
SELECT COUNT(DISTINCT user_id)
FROM subscriptions
WHERE status = 'active'
  AND current_period_end > CURRENT_TIMESTAMP
```

### Session-to-purchase conversion
```
SELECT
  s.session_id,
  MAX(CASE WHEN e.event_type = 'purchase.complete' THEN 1 ELSE 0 END) AS converted
FROM sessions s
LEFT JOIN user_events e
  ON s.session_id = e.session_id
  AND e.event_type = 'purchase.complete'
GROUP BY 1
```
